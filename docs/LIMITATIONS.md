# Remaining limitations and explicit demo constraints

- Local operation assumes a trusted machine and private browser session tokens. Operator credentials are generated/configured privately at runtime. Hosted operation uses HTTPS and a private environment credential; broader production use still needs a real identity system, rate limits, monitoring and a security review. The visual switcher is not authentication.
- Run exactly **one Uvicorn worker and one backend instance**. SQLite serializes writes and the single monitoring loop owns persistent recovery. Horizontal workers, distributed queues and multi-region deployment are outside this local architecture.
- Payments, bank reconciliation, refunds, stores, inventory partner checks, rider assignments, service-token refresh, delivery and notifications are local simulated adapters. No money, SMS, cold-chain fulfilment or PagerDuty integration exists. The payment ledger deterministically reconciles an unknown demo debit as captured. That is a fixture outcome, not a real bank lookup.
- Backup-store availability is an explicit always-available local same-item fixture. Catalogue reservations are real transactional database accounting within the demo, but partner-hub stock is not a separately integrated warehouse inventory. Substitutes are limited to the two verified equal-price grocery combos; medicines/infant formula are never substituted.
- Address correction is an exact local lookup of 560039 to a labelled demo pickup desk at 560038. It requires customer acceptance and never guesses a person's address. Other rejected addresses require manual review/cancel/new slot; accepting a new slot alone does not fix the original address or stock fault.
- Models use synthetic data only. The measured probabilities are uncalibrated and do not establish real-world performance or action safety. Error class signals are intentionally strong; the evaluation report explains this limitation. Observed response times in model inputs are simulator service signals, not measured real-provider latency. No hardcoded confidence is used.
- There are no independently verified operator outcome labels. Approvals/rejections/changes are stored as preferences but excluded from training. Retraining currently regenerates the reproducible synthetic dataset and reports zero usable labelled feedback. It does not pretend to learn from approval clicks.
- Gemini prose generation is optional and unverified with a live API key in this delivery. Without configuration or on timeout/error, offline template facts remain authoritative. The adapter cannot choose actions, modify scores, or execute tools. Matching playbook retrieval is exact JSON lookup, not vector search.
- Delivery estimates use simulated completed deliveries. Until five completions exist, the labelled 35-minute baseline and documented error penalties are assumptions. Incident repair estimates remain unavailable until measured completion. A new slot can resolve a rider-delay agreement but does not resolve a stock/store/address fault.
- Deadline warnings are deduplicated once per order. A newly accepted slot does not create a second warning. Delivery stages only advance through explicit demo operations; there is no real rider telemetry or automatic delivery claim. Monitoring after a missed deadline records a late warning honestly.
- A process crash interrupts a training job, which is marked FAILED on restart. The previous usable model remains active. Recovery/settlement jobs are restart-safe; training jobs are not automatically resumed. Artifacts are versioned locally; this is not a managed model registry or real production calibration pipeline.
- Current dashboard/monitor implementations favour readability and local demo volumes. Paginated lists are bounded; history CSV is capped at 10,000 matching rows. Statistics/monitoring scan local records, which should be replaced with indexed aggregate work for large deployments.
- WebSockets use durable invalidation events plus HTTP snapshots, not a client-side replay cache. Reconnection resynchronises the latest state and suppresses duplicate/older events. Historical events remain available to the operator feed; a disconnected client is not promised every transient toast.
- Formal verification is limited to the included tests, Chromium desktop/mobile viewports and the supplied reference. No real devices, other browser engines, real payment providers or external notification delivery were tested. The test stack emits a non-failing Starlette/httpx deprecation warning; pinned dependencies passed the included suite.
